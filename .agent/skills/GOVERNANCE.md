# Skill 维护契约

Skill 是任务执行入口；正文留在 `.agent/skills/`，客户端适配只负责发现。

## 有用的结构

每个 Skill 至少说明目标、决策、步骤、关键边界与验收；参数只在实际需要时列出。复杂分支放单层 references，主文件直接说明何时读取。不要为了固定行数删除关键约束，也不要以标题或字数评分替代正确性。

新增技能前先确认任务无法由现有技能清楚覆盖。修改架构/命令/接口时，同步 Skill、references、索引、adapter、样例和对应测试。

## 校验层次

1. **资产完整性**：frontmatter、索引、目录名、adapter 同步，链接/参照存在，无未完成模板。
2. **命令契约**：文档命令符合 CLI 帮助，非法输入、名称冲突与非空目标有明确失败行为。
3. **行为验收**：在临时项目完成真实任务，生成后测试状态、注入、导航、错误与生命周期。
4. **回归**：模板变化必须覆盖已有生成场景，不以“文件生成了”代替“项目能运行”。

完整门禁使用 `python3 blueprint.py validate`；分项入口为 `python3 blueprint.py check ai` 与 `python3 blueprint.py check architecture`。Windows 用 `py -3`。

## 冷启动验收题

- 只给入口文件，创建改名后的最小项目并构建选定平台。
- 在新项目加入 API 列表，验证加载失败不能显示为空结果。
- 加入本地 Feature，验证临时目录与退出清理。
- 加入两个业务 module，验证路由注册、会话切换和旧结果拒绝。
- 注入一处违规跨层 import，检查门禁能否定位；修复后复测。

维护者应记录命令和结果，失败时定位指令/脚手架/代码哪一层有缺口。不同模型的执行结果不是自动一致的，原生发现本身也不是完成证据。
