# 蓝图实现与验证记录 · 2026-09-29

本轮将蓝图的架构规则、受检示例、生成器、AI Skills 与自动检查连成可复现流程。Flutter 固定 3.47.2，Dart 3.13.2；保留兼容依赖组合，没有进行无关升级。

## 已落地

- 默认新项目：精简 App、类型化路由、Riverpod/Freezed 生成能力及 koi_core；不默认启用认证、业务网络、数据库或模块。
- 受检示例：精简宿主，API/展示/本地草稿三类 Feature，最小模块，双模块宿主；生成器直接复用样例源码和测试。生成项目把可选参照保存在隐藏快照目录，活动成员仍由 Pub workspace 管理。
- 统一命令：create、feature、module、validate、build；已有脚本与 Makefile 保留兼容入口。支持改名、空格/中文路径、平台筛选、依赖补齐、原子失败回滚与重复创建保护。
- 模块具有独立公开入口、路由与导航贡献、显式会话拥有者；切换释放旧订阅/任务，拒绝旧结果，宿主基础设施独立存活。类型化路由只导出公开类型，避免生成的注册表符号冲突。
- 9 个规范 Skills 与 Codex/Claude/Cursor 轻量入口；9 条架构规则、AI 资产检查、模板成员登记检查、精确例外与失效例外检查。
- CI 含源码验证、真实改名生成集成测试，以及 Linux/macOS/Windows 三宿主上的六端构建任务。

## 独立 AI 演练

使用不共享本次实现会话/本机记忆的临时 Codex 执行，从 AGENTS.md 读取仓库自身说明。五类任务为 Web-only 初始化、API 目录、本地草稿、纯展示帮助页、可选 warehouse_ops 模块及模块内 API。

独立执行者完成路由和注入，保留所有检查规则和 80% 门槛：47 项应用/模块测试、96.79% 手写覆盖率、模块启用/关闭两种 Web release 构建通过。首次快照的完整验证诚实失败于一处文档死链；同时暴露模块公开入口泄漏生成路由注册表的问题。两项都已在蓝图源头修复，路由导出加了编译回归。

首轮执行期间主线还在修改源仓库，因此它验证的是保留的生成快照。后续将演练工程的工具和 AI 文档同步到冻结后的蓝图源版本，保留业务实现、测试与锁文件，再做完整复核；不能把上游资产更新说成检查文件从未改变。

复核完整 `validate` 通过：47 项行为测试、36 项 Python 回归、36 项架构正反例、3 项覆盖率源码归属回归，覆盖率 **96.79%（483/499）**。94 个受保护业务、测试和依赖文件在同步与验证前后哈希不变；227 个同步资产与更新记录一致，9 个执行检查文件与当前源逐字节一致。复核保留了初次失败和上游更新差异，没有删除或绕过门禁。

独立进程中的 Chrome 启动失败，没有运行到浏览器断言。主代理随后在正常本机环境执行同一测试，**真实浏览器存储在重新创建偏好服务、repository 与 ProviderContainer 后仍可读取，1 项通过**。

## 本轮发现后修复

1. data/application 二选一、provider 位置和普通 Widget 参数规则冲突；统一为可共存，Feature provider 固定 presentation/providers。
2. 过时的 AsyncValue API、错误被空集合掩盖和未声明的保活策略；改为已编译的显式状态与生命周期测试。
3. 脚手架只建目录、校验硬编码旧 App、模块缺失依赖；改为实际源码/测试生成和 Pub 成员发现。
4. 生成文档把可选包当作现存路径；集中样例地图并在真实生成项目验证链接。
5. 宿主覆盖率扫描误纳入嵌套成员；限定每个成员自己的 lib，保留缺测拒绝测试。
6. 模块入口重导出 `$appRoutes`；改为显式 `show` 路由类型，宿主通过 catalog 组合。
