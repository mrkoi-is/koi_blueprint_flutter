# v0.3.0-rc.1

本版本为源码预发布，整合 `v0.2.0` 的测试与升级工具、`v0.3.0-android-rc.1` 的诊断能力，以及本轮国际化修复。目标范围为 minimal / workbench 蓝图和默认能力，支持英文、简体中文、繁体中文，面向 Android、iOS、macOS、Windows、Linux、Web。六端完整国际化验收尚未完成。

已于 2026-11-17 发布：[GitHub Release](https://github.com/mrkoi-is/koi_blueprint_flutter/releases/tag/v0.3.0-rc.1)。同名 tag 固定提交 `046850e3f71fff696b0326cd8b3354d0199a2d99`；发布当时的正式版 Latest 为 `v0.2.0`。以下验证结果对应这个发布提交，后续工作树变更需另行验证。

## 变更

- App 的语言选择、偏好恢复及回退统一使用 ARB 驱动的 locale policy；中文脚本优先于地区推断，兼容旧语言标签。
- 新建和后装诊断能力均补齐 Apple 三语声明及 `InfoPlist.strings` 打包；保护自定义权限说明，兼容 Xcode/CocoaPods 工程重排，并维护构建后的受管文件基线。
- 修复 Windows 宿主生成 Apple 工程时的 CRLF 兼容，保留原换行格式，覆盖重复安装与两阶段装配。
- Android 前台诊断通知与已有通知渠道支持三语，保留渠道设置；LAN 网页标题、语言标记及导出失败提示完成翻译。
- 保留已发布诊断版本的 SSE 首帧订阅、活跃连接关闭、慢磁盘日志分段轮转和生成器浏览器烟测修复。
- 保留 `v0.2.0` 的定向测试、Golden、持久化、升级事务及原生运行监督工具；修复 AI 会话异常清理、已有工程 CI 的依赖/生成准备和 Dio 流式响应诊断结束时机。
- 合入主分支的 analyzer 14.5.0、build_runner 2.16.2 和 checkout 更新。

## 旧项目迁移

从两个历史基线（`v0.2.0-rc.1` 对应的固定提交、`5ec56a9`）直接升级到本候选，会因 root/App/koi_core 的依赖变化而要求人工迁移。CI 的 `Migration boundary` 矩阵验证这三个明确冲突、拒绝应用及项目内容/来源记录不变；它不表示自动升级、升级后构建或重启验收通过。

请先备份工程，按 [升级指南](../upgrade-guide.md) 在隔离分支审阅依赖、App 装配和原生配置；不要通过伪造基线或删除冲突强行应用。既有升级工具保留原有的受管变更能力和拒绝语义，本版本未扩大自动依赖迁移范围。
