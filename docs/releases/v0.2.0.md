# v0.2.0 发布准备（冻结时记录）

该版本已发布于 2026-11-17，最终提交、CI 与验收结果见 [GitHub Release](https://github.com/mrkoi-is/koi_blueprint_flutter/releases/tag/v0.2.0)。以下正文保留候选冻结时的说明；后续国际化与诊断整合见 [v0.3.0-rc.1](v0.3.0-rc.1.md)。

目标为可复核的 AI 测试工具及存量蓝图工程升级。本文件是候选说明，不能单独证明最终提交、远端工作流或目标设备已经通过，也不代表版本已经发布。

## 相对 v0.2.0-rc.1 的范围

候选包含定向 VM/Chrome 测试、按版本选择的 macOS ARM64 Golden、workspace 互斥和可复核结果，以及 Workbench 真实 UI、持久化和桌面跨进程回归。源仓与 minimal、Workbench 下游项目使用对应的 CI 执行集合。自候选版已有的 ARCH014 异步生命周期、Windows SDK/路径/覆盖率及桌面和 Web 媒体兼容修复也包含在范围内。完整门禁继续包含浏览器测试与 80% 手写代码覆盖率；目标平台构建和真实运行分别记录。

## 使用与升级

先按 [工具清单](../tools.md) 准备固定 SDK，使用定向入口诊断具体成员和测试文件；结果只证明明确列出的范围。完成变更后仍运行完整验证。Golden 使用本地支持的 macOS 主版本对应基线，像素比较不放宽；新增或替换图片需要审阅。

已有 schema 2 项目应先备份，并按 [下游工程升级指南](../upgrade-guide.md) 使用新源码预览计划。审核每项冲突和依赖差异后，才在隔离分支或副本中应用并验证；回退会保护后续编辑。缺少可信基线、未解决冲突、不能可靠解析的依赖及不支持的删除均需人工处理，不能把部分应用记为完整升级。schema 1 或缺失来源的项目需要按指南人工迁移。

Dart MCP 应通过独立测试入口和受控会话接入；读取状态、保存、停止、重开及读回需要各自验证。预构建 macOS App 的会话限制及操作见 [Workbench 测试策略](../test_strategy.md) 和项目继承的调试入口说明。Chrome 热重启未列为支持路径，Windows 会话进程管理未实现。

## 发布证据与平台边界

正式验收须关联同一候选的源码身份、环境、完整门禁、连续测量、旧版升级演练和远端工作流的 job/attempt；下载原始事件、结果及图片并校验哈希。CI 必须证明 App 两个入口和 Golden 实际执行数量，Workbench 需验证 W1–W6 以及 Linux、macOS、Windows 的跨进程写读。Linux 真实媒体还须检查进程监督结果和 reporter 完成事件，超时不视为通过。

Native 文件存储与 Web IndexedDB 的行为分别取证；跨版本 IndexedDB 的同源 UI 读回须单独验证。Flutter 测试驱动或 fixture 文件选择器不证明系统选择器、OS 退出事件或实体扬声器，Android/iOS 构建也不等于设备运行。未实测的平台和浏览器在验收记录中保留未执行状态。

本地研究及历史验收目录不进入生成项目，不能替代候选的可下载证据；版本标签、正式发布和分发另按授权执行。
